# R on strix

System R 4.6 with **r2u binaries**, so `install.packages()` installs a compiled binary and is
fast. Do not reach for conda or build from source to "avoid slow compiles" - that problem does
not exist here. Repo-tracked packages go in `lists/r-packages-*.txt` and install via
`./bootstrap.sh 50`.

IDEs: Positron, RStudio, VS Code. `radian` for a better console.

## Project reproducibility

The Shiny apps use **renv** (`preclinical-study-analysis-shiny`, `Survival_Shinny_App`):
`renv::restore()` before running, `renv::snapshot()` after adding a package. Do not
`install.packages()` into an renv project without snapshotting - it silently desyncs the lock.

`lab-bioinfo-templates` does **not** use renv; it has `install_packages.R` and an
`environment.yml`, and renders as a Quarto site.

## lab-bioinfo-templates: the rule that matters

Every template ships **synthetic example data only**, generated by the
`data/simulate_data.R` / `simulate_data.py` script in its own folder. No experimental or study
data is in the repo, and no figure or statistic in the gallery came from a real dataset.

When adding a template, add its simulate script too. Never commit real study data to make an
example look better - the gallery is public
(https://aleponce4.github.io/lab-bioinfo-templates) and the claim of synthetic-only is load
bearing.

Structure: `templates/<NN>-<name>/`, `_quarto.yml` for the site, `custom.scss` for styling.
CI renders the site, so a template that fails to render breaks the build.

## Shiny apps in this account

- `Alphavirus-results-browser` - DEG, gene sets, enrichment, WGCNA modules, network
- `preclinical-study-analysis-shiny` - longitudinal mouse studies from spreadsheet input
- `Survival_Shinny_App`

Data files stay outside the repo (`/data/`), loaded by path from config - not committed.
